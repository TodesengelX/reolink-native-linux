# Architecture Proposal: performance-first

**Angle:** Maximize video performance and UI fidelity (16-stream grid with zero-copy hardware decode, pixel-accurate Reolink skin), long-term maintainability, and a redistribution-clean license — as a fully native (no Electron/web-wrapper) Linux desktop app. The design principle is "own the media pipeline, isolate the render backend per GPU vendor, and reimplement the Reolink protocols in C++ only from permissively-licensed references (MIT reolink_aio), never from AGPL neolink."

## Tech Stack

C++20 + Qt 6 (LGPLv3, dynamically linked): Qt Quick/QML for the camera grid, PTZ joystick, and playback timeline; Qt Widgets for the dense Device/Client settings dialogs (embedded via QQuickWidget/window-container). Media: FFmpeg libavformat/libavcodec/libswscale/libswresample built LGPL-only (no --enable-gpl, no x264/x265 — decode + remux only) for RTSP/FLV ingest, hardware decode, stream-copy recording, and JPEG snapshots. Render: custom per-tile QRhiWidget/QOpenGLWidget with a vendor-split zero-copy path — VAAPI→DMA-BUF→EGLImage→GL_TEXTURE_EXTERNAL_OES on Intel/AMD, CUDA-GL interop on NVIDIA — with NV12/P010 YUV→RGB (and 10-bit tone-map) done in a fragment shader; software libavcodec decode + texture-upload as the universal fallback. Audio: PipeWire (native pw_stream, Pulse-compat as fallback) for playout and mic capture. Protocol clients (reimplemented in C++ from MIT-licensed reolink_aio): libcurl (HTTP-CGI JSON API — login/token, GetEnc, PTZ, Search/Download, Snap), nlohmann/json for payloads, OpenSSL 3 for the Baichuan port-9000 AES-CFB handshake (battery/RTSP-less cams and event push), pugixml for Baichuan/ONVIF XML, hand-rolled minimal SOAP/WS-Discovery over libcurl for ONVIF discovery + event subscription (avoiding GPL gSOAP). State: SQLite (device list, layouts, recording index) + libsecret (credentials). Build: CMake. Packaging: Flatpak (primary, org.kde runtime) + AppImage; all third-party libs are LGPL/MIT/Apache and dynamically linked, so the app itself can remain proprietary and freely redistributable.

## Rationale

Against the weighted goals — video performance, UI fidelity, maintainability, clean licensing — Qt 6 + a hand-owned FFmpeg pipeline dominates the alternatives. (1) UI fidelity: Reolink's client is a heavily custom-skinned dark UI (16-pane grid, floating per-pane toolbars, color-coded scrubbable timeline, PTZ joystick, Clear/Balanced/Fluent stream toggles). QML's GPU-composited scene graph gives pixel-perfect, HIG-unconstrained theming and cheap animated custom controls; libadwaita (the GTK4 path) actively resists non-GNOME skinning, making a 1:1 clone a fight. The Reolink client is itself widely believed to be Qt, further lowering replication risk. (2) Video performance / zero-copy: for a 16-tile grid the binding constraints are GPU decode sessions and render copies, not the toolkit. Owning libavformat/libavcodec directly (one demux+decode worker per stream, present-latest ring buffers, a single shared GL context drawing all tiles) gives per-packet control over RTSP transport, low-latency flags, per-stream hardware/software fallback, and remux-to-MP4 without re-encode — control that GStreamer's element negotiation hides and makes harder to reason about at 16x. The grid subscribes to each camera's sub-stream and only opens the main stream on maximize, which is the decisive 5–10x decode/upload saving. (3) Licensing for redistribution: every dependency is dynamically-linkable LGPL (Qt, FFmpeg LGPL build), MIT (nlohmann/json, pugixml, curl license), or Apache-2.0 (OpenSSL 3). The protocol layer is reimplemented in C++ strictly from MIT reolink_aio and the official HTTP API PDF — never from AGPL neolink — so nothing forces source disclosure and the binary can be shipped on Flatpak/AppImage/deb cleanly. (4) Maintainability: Qt has the largest desktop ecosystem, mature tooling (Qt Creator/Designer), a large hiring pool, and long-term commercial backing; C++ keeps the GUI, the FFmpeg pipeline, and the GL/CUDA interop in one language and one memory/threading model. GTK4+GStreamer is the credible runner-up (cleanest LGPL, best turnkey dmabuf sink) but loses on custom-skin effort, on the NVIDIA dmabuf gap being invisible to the app, and on lower per-frame control; Slint's video path is example-grade, disqualifying it for a many-camera NVR.

## Architecture Layers

| Layer | Responsibility | Key Libraries |
|---|---|---|
| Device & Protocol layer | Discovery (LAN scan, ONVIF WS-Discovery, UID/P2P), per-device session and token lifecycle (read leaseTime dynamically, refresh with ~60s margin, truncate password to 31 chars, avoid Logout-without-token firmware bug), all configuration/control commands (GetEnc/SetEnc, Display/ISP, detection/alarm, PTZ via HTTP-CGI PtzCtrl, recording Search/Download/Snap), Baichuan port-9000 client for RTSP-less battery cams and real-time event push, and ONVIF event subscription as an alternative push source. Emits a clean C++ device model consumed by UI and media layers. | libcurl, nlohmann/json, OpenSSL 3 (Baichuan AES-CFB + HTTPS), pugixml (Baichuan/ONVIF XML), hand-rolled SOAP; reimplemented in C++ from MIT reolink_aio + official API PDF |
| Media pipeline layer | RTSP (TCP default, low-delay flags) and HTTP-FLV ingest, one demux+decode worker thread per stream owning its own AVFormatContext/AVCodecContext, hardware decode with per-stream software fallback for exotic HEVC profiles, present-latest frame ring buffers (drop-oldest so a slow camera never stalls the grid), stream-copy remux recording of all 16 main streams to fMP4 (Annex-B→AVCC/HVCC), keyframe-seek + decode-to-target playback scrubbing, and JPEG snapshots. | FFmpeg libavformat/libavcodec/libswscale (LGPL-only build), VAAPI (Intel/AMD), NVDEC/CUVID (NVIDIA) |
| Render layer | Zero-copy compositing of all tiles from a single shared GL/Vulkan context: Intel/AMD path exports the VA surface to DMA-BUF and imports it as an EGLImage into a GL_TEXTURE_EXTERNAL_OES sampler; NVIDIA path keeps frames in CUDA memory and uses CUDA-GL interop (no DMA-BUF export on NVIDIA); NV12/P010 YUV→RGB, limited/full-range and 10-bit tone-mapping in a fragment shader; upload-and-convert as portable fallback. Two backends selected at runtime by GPU vendor. | Qt RHI / QOpenGLWidget / QRhiWidget, EGL (EGL_EXT_image_dma_buf_import), CUDA-GL interop, GLSL shaders |
| Audio layer | Decode AAC / G.711 (a-law/mu-law) from the focused pane's AVFormatContext, resample to the device rate, drive A/V sync for the selected stream, route only the active pane's audio, and implement two-way talkback: capture mic, encode G.711, packetize RTP over the ONVIF Profile-T backchannel via a small custom RTSP/RTP client (FFmpeg's RTSP muxer backchannel support is insufficient). | libavcodec, libswresample, PipeWire (pw_stream, Pulse-compat fallback), custom RTP backchannel |
| Application & UI layer | QML shell: 16-pane grid (GridLayout/Repeater) with layout presets (1/4/9/16), maximize/fullscreen pane transitions, per-pane floating toolbar (Clear/Balanced/Fluent, snapshot, record, talk, PTZ, digital zoom), animated PTZ joystick + presets/patrol, color-coded playback timeline with wheel-zoom and alarm-type filters, add-device wizard, scrollview auto-cycle. Qt Widgets host the dense Device (Stream/Display/Detection/Alarm) and Client settings dialogs. Owns view-model state, persists layouts and pane→camera bindings. | Qt Quick/QML, Qt Widgets, Qt Quick Controls |
| Persistence, config & packaging | Store the device tree, last-used grid layout and pane assignments, and a local recordings index; keep credentials in the OS keyring; ship as a self-contained bundle with all LGPL/MIT/Apache libs dynamically linked and license texts included so the proprietary app remains freely redistributable. | SQLite, libsecret, CMake, Flatpak (org.kde runtime) + AppImage (linuxdeployqt) |

## Risks

- NVIDIA has no DMA-BUF export for VA surfaces, forcing a second CUDA-GL interop render backend — this roughly doubles render-path development and test surface, and must be validated on real Intel/AMD/NVIDIA hardware on both Wayland and X11 before committing.
- The Baichuan port-9000 protocol (nonce/AES-CFB handshake, event push, battery-cam video, P2P/UID NAT-hole-punching) is complex and must be reimplemented in C++ strictly from MIT reolink_aio — copying from AGPLv3 neolink would taint the whole product's redistribution license. This is a legal firewall the team must enforce in code review.
- FFmpeg build discipline is load-bearing: accidentally enabling --enable-gpl or linking x264/x265/GPL filters would make the binary GPL and break clean redistribution. Only LGPL decoders/muxers are needed (decode + stream-copy), so the build config must be pinned and audited.
- HEVC edge cases (Main10 / 4:2:2, unusual B-frame or GOP configs) are rejected by some VAAPI drivers; each stream needs an independent silent fall-through to threaded software decode so one exotic camera profile never kills the grid.
- Remote UID/P2P access depends on Reolink's dispatcher/relay infrastructure (p2p*.reolink.com) and reverse-engineered packet formats that can change with firmware, and the relay is effectively MITM-capable — remote viewing reliability is outside the app's control and may need periodic maintenance.
- Two-way audio uses the ONVIF Profile-T RTSP backchannel, which FFmpeg's RTSP muxer supports poorly; a bespoke RTP client is required and must be verified bidirectionally (Wireshark), adding protocol-level test burden.
- UI fidelity is a moving target: Reolink is proprietary and updates its client; exact grid presets, floating-toolbar icon order, timeline color mapping, and capability-gated controls (PTZ vs fixed, AI vs basic motion, presence of the Balanced stream) must be reverse-engineered per build and kept in sync.
- Firmware/auth quirks (dynamic leaseTime rather than a fixed 3600s, 31-char password truncation, Logout-without-token breakage, HTTPS-only newer firmware with RTSP/ONVIF disabled by default) must all be handled defensively, or devices will intermittently fail to connect.
- Qt must stay dynamically linked to preserve LGPLv3 compliance without a commercial license; any static-link shortcut would trigger relink/object-file obligations undesirable for a proprietary redistributable.
- 16 simultaneous main-stream 1080p/4K tiles will exceed practical decode/upload/shader budget — the sub-stream-for-grid / main-stream-on-maximize strategy is mandatory, and cameras that cannot expose a usable sub-stream or short GOP will degrade the grid; verify sub-stream availability across the target camera lineup early.
